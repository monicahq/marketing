Une page de comparaison serait facile à organiser. Mettre Monica dans la première colonne, choisir les fonctionnalités que Monica a et distribuer généreusement des coches vertes.

Félicitations à nous pour avoir gagné le concours que nous avons conçu nous-mêmes.

Je ne trouve pas cela particulièrement utile pour quelqu’un qui choisit un logiciel.

### Expliquer nos propres décisions

D’autres produits peuvent être excellents sans partager nos priorités. Un outil conçu pour des équipes commerciales, un carnet privé et un CRM personnel résolvent des problèmes voisins mais différents.

Nous devrions pouvoir expliquer pourquoi Monica est open source, pourquoi l’auto-hébergement compte et pourquoi nous tenons à documenter les relations. Ces arguments n’exigent pas de faire passer le produit de quelqu’un d’autre pour ridicule.

Cela ne veut pas dire refuser de remarquer les bonnes idées ailleurs. [Nos principes](/fr/manuel/principles/) décrivent ouvertement nos sources d’inspiration. Apprendre d’une autre équipe est sain. Copier automatiquement chaque fonctionnalité qu’elle sort est une autre activité.

Cela n’empêche pas non plus de répondre à une question précise sur les différences. Si quelqu’un a besoin d’une capacité que Monica n’a pas, nous devrions le dire avec exactitude plutôt que de changer de sujet pour parler de notre collection supérieure de pandas.

Le danger est de laisser le calendrier de sorties d’un autre devenir notre stratégie de produit. Une fonctionnalité peut être utile dans leur contexte et fausse dans le nôtre.

Je préfère expliquer Monica assez clairement pour que les gens fassent leur propre comparaison. Ils savent mieux ce dont ils ont besoin qu’un tableau construit pour que nous gagnions.
