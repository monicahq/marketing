We hebben veel andere open source projecten, en dezelfde vraag komt steeds terug. Waarom zijn we gek genoeg om onze code als open source uit te brengen?

Ten eerste kunnen de meeste commerciële producten relatief gemakkelijk worden nagebouwd. Dat geldt nog sterker in het tijdperk van AI. De meeste hebben geen duidelijk concurrentievoordeel in hun code. Dat is natuurlijk niet het geval voor bedrijven als Stripe, maar voor de overgrote meerderheid van de producten, die in wezen CRUD-applicaties zijn, wel. Onze geheime saus is niet de code zelf; het is alles wat eromheen zit: de community, het publieke imago, het ecosysteem en het vertrouwen dat we in de loop der jaren hebben opgebouwd.

Ten tweede geloven we sterk dat we veel betere code zullen produceren als iedereen er een blik op kan werpen. Als je code publiceert die iedereen kan lezen, zet dat een soort druk op je. Elke regel code die er staat getuigt van wie je bent als ontwikkelaar. Dus zorg maar dat wat je publiceert het best mogelijke is en weerspiegelt waarin je gelooft. Natuurlijk maakt open source code niet automatisch goed, maar het geeft iedereen de kans om haar beter te maken.

Ten derde is een product beter als mensen eraan kunnen bijdragen. Die bijdragen moeten natuurlijk aansluiten bij de waarden en de richting van het project. Als ze dat doen, is het geweldig. Mensen van over de hele wereld verhelpen een bug, verbeteren een functie of voegen iets volledig nieuws toe. En omdat het project onder de AGPL is gelicentieerd, kunnen mensen die op ons werk voortbouwen het niet zomaar nemen, aanpassen, als dienst aanbieden en die aanpassingen voor zichzelf houden.

Een open source project zorgt ook voor vertrouwen en transparantie. Op de instantie die wij beheren (dus [my.monicahq.com](https://my.monicahq.com)) wordt de code uit de [GitHub-repository](https://github.com/monicahq/monica) rechtstreeks, zonder enige wijziging, in productie gezet. Als je software persoonlijke informatie opslaat, is het nog belangrijker dat je kunt begrijpen hoe het onderliggende systeem werkt, zodat je het systeem kunt vertrouwen dat je kostbare gegevens bewaart.

We verwachten niet dat iedereen onze code leest. De meeste mensen zullen er nooit één regel van bekijken, en dat is prima. Waar het om gaat is dat iedereen het kan. Je hoeft niet blind alles te geloven wat we over privacy en beveiliging zeggen. Je kunt het zelf controleren of vertrouwen op mensen die de technische kennis ervoor hebben.

Open source geeft je ook vrijheid. Als je niet bevalt hoe wij Monica runnen, kun je het zelf hosten. Als je het niet eens bent met de richting van het project, kun je het forken. Als je iets wilt toevoegen wat wij niet willen toevoegen, kun je het zelf doen. We hoeven het niet over alles eens te zijn om jou te laten profiteren van ons werk.

Open source zijn betekent niet dat alles gratis moet zijn. Software ontwikkelen kost enorm veel tijd en een dienst draaiende houden kost geld. Wij zien geen tegenstelling tussen een open source product bouwen en er een duurzaam bedrijf omheen bouwen. Sterker nog, geld verdienen aan het project is waarschijnlijk een van de beste manieren om ervoor te zorgen dat we er nog vele jaren aan kunnen blijven werken.

Open source zijn betekent ook niet dat we verplicht zijn elke functie te bouwen waar de community om vraagt. We hebben een visie voor het project, en het is onze verantwoordelijkheid die te beschermen. Iedereen is vrij om bij te dragen, net zoals wij de verantwoordelijkheid hebben om te beslissen wat er in het project thuishoort.

Er is ook iets heel moois aan iets de wereld in sturen waar mensen van kunnen leren. We hebben in de loop der jaren enorm veel geleerd van het lezen van andermans code. Het meeste van wat we als ontwikkelaars weten is, op de een of andere manier, het resultaat van iemand die besloot zijn werk te delen. Ons eigen werk beschikbaar stellen aan anderen is een manier om iets terug te geven.

Last but not least maakt open source het mogelijk dat een project in de loop van de tijd door de community in stand wordt gehouden, voor het geval de oprichters hun motivatie verliezen of door een bus worden overreden. In dat geval kan de software haar oorspronkelijke oprichters overleven, en dat is een goede zaak.

Dit is bijzonder belangrijk voor Monica. We vragen je om je leven vast te leggen in software die je misschien tientallen jaren gebruikt. De mogelijkheid om bij die informatie te komen mag niet afhangen van de vraag of twee ontwikkelaars op een zondagmiddag nog zin hebben om aan een project te werken.

Uiteindelijk willen we niet dat het bestaan van Monica van ons afhangt. We zouden het geweldig vinden om mensen Monica te zien gebruiken en verbeteren lang nadat wij ermee zijn gestopt.
