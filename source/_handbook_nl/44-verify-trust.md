“Vertrouw ons” is een makkelijke zin om op een website te zetten. Er is nauwelijks techniek voor nodig.

Bij software als Monica geven we mensen liever manieren om specifiekere vragen te stellen. Wat doet de code? Welke informatie heeft een functie nodig? Kan ik de applicatie zelf draaien? Wat verandert er tussen versies?

Open source helpt die vragen beantwoordbaar te maken.

### Inspectie is een mogelijkheid, geen vereiste

De meeste mensen die Monica gebruiken lezen de code niet. Dat is prima. Een persoonlijke CRM kiezen mag niet vereisen dat je PHP-ontwikkelaar wordt.

Wat telt is dat technisch onderlegde mensen haar kunnen onderzoeken, uitleggen en ter discussie stellen wat wij zeggen. Ze hebben onze toestemming niet nodig om een fout aan te wijzen.

Er zijn grenzen. Openbare broncode alleen bewijst niet hoe een bepaalde server is geconfigureerd of beheerd. Ze toont niet aan dat elke kwetsbaarheid is gevonden. Een zelf gehoste installatie kan ook verkeerd geconfigureerd zijn.

Die onderscheiden doen er meer toe dan een aantrekkelijke badge “open source = veilig”.

[Waarom open source](/nl/handboek/why-open-source/) legt de bredere beslissing uit. Hier gaat het om verantwoording: vragen over persoonlijke informatie verdienen specifieke uitleg, ook waar we te weinig weten om iets te beweren.

We moeten ons op ons gemak voelen bij verificatie die problemen vindt. Dat hoort bij het doel ervan.

Ik wil dat mensen Monica vertrouwen om redenen die ze kunnen begrijpen. Onze panda ziet er eerlijk uit, maar ik zou hem niet als beveiligingsaudit accepteren.
