„Vertrauen Sie uns“ ist ein Satz, der sich leicht auf eine Website schreiben lässt. Er erfordert sehr wenig Engineering.

Bei Software wie Monica geben wir den Menschen lieber Wege, genauere Fragen zu stellen. Was tut der Code? Welche Informationen braucht eine Funktion? Kann ich die Anwendung selbst betreiben? Was ändert sich zwischen den Versionen?

Open Source hilft, diese Fragen beantwortbar zu machen.

### Prüfen ist eine Möglichkeit, keine Pflicht

Die meisten Menschen, die Monica nutzen, werden den Code nicht lesen. Das ist in Ordnung. Wer sich für ein persönliches CRM entscheidet, sollte dafür nicht PHP-Entwickler werden müssen.

Wichtig ist, dass technisch versierte Menschen ihn prüfen, erklären und hinterfragen können, was wir sagen. Sie brauchen keine Erlaubnis von uns, um auf einen Fehler hinzuweisen.

Es gibt Grenzen. Öffentlicher Quellcode allein beweist nicht, wie ein bestimmter Server konfiguriert ist oder betrieben wird. Er zeigt nicht, dass jede Schwachstelle gefunden wurde. Auch eine selbst gehostete Installation kann falsch konfiguriert sein.

Diese Unterscheidungen sind wichtiger als ein hübsches Abzeichen „Open Source = sicher“.

[Warum Open Source](/de/handbuch/why-open-source/) erklärt die weitergehende Entscheidung. Hier geht es um Rechenschaft: Fragen zu persönlichen Informationen verdienen konkrete Erklärungen, auch dort, wo wir nicht genug wissen, um eine Aussage zu treffen.

Wir sollten mit einer Überprüfung, die Probleme findet, gut leben können. Das gehört zu ihrem Zweck.

Ich möchte, dass Menschen Monica aus Gründen vertrauen, die sie verstehen können. Unser Panda sieht ehrlich aus, aber als Sicherheitsaudit würde ich ihn nicht gelten lassen.
