Eine Notiz über den Lieblingskuchen von jemandem kann nächste Woche nützlich sein. Eine Geschichte über Ihre Großmutter kann in zwanzig Jahren viel wichtiger sein.

Das ist für Software eine ungewöhnliche Zeitspanne. Die Branche begeistert sich für ein JavaScript-Framework ungefähr so lange, wie es dauert, es zu installieren. Die Geschichte Ihrer Großmutter hat währenddessen kein einziges Mal ihr Build-System gewechselt.

Wir wollen, dass Monica auf der Zeitskala der Informationen funktioniert, die Menschen darin ablegen.

### Langlebigkeit hat Folgen

Sie macht Wartung wichtig. Sie macht verständlichen Code wichtig. Sie macht [die Möglichkeit zu gehen](/de/handbuch/leaving/) wichtig, denn eine Erinnerung sollte nicht ausschließlich davon abhängen, ob wir noch Lust haben, eine bestimmte Anwendung zu pflegen.

Sie bedeutet auch, über die ursprünglichen Autoren hinauszudenken. Könnte ein anderer Entwickler verstehen, warum eine Beziehung so funktioniert? Könnte jemand die Software betreiben, ohne mich zu fragen, was eine rätselhafte Einstellung bedeutet?

Open Source macht das auf eine Weise möglich, wie es geschlossener Code nicht tut. Es macht es nicht automatisch möglich. Ein verlassenes Repository mit unmöglichen Installationsanweisungen ist trotzdem ein verlassenes Repository.

Zwanzig Jahre sind ein Anspruch, keine Hosting-Garantie. Ich kann nicht versprechen, wie mein Leben, das Internet oder Monica dann aussehen werden. Ich kann Entscheidungen bevorzugen, die mehr Möglichkeiten offenlassen.

Die Frage ist nicht, ob eine Funktion heute modern aussieht. Es ist, ob die Informationen, die sie enthält, nützlich bleiben können, wenn die Mode vorbei ist. Es wird jede Menge Moden geben. Im Idealfall weniger verlorene Erinnerungen.
