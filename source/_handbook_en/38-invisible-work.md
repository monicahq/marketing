A new feature is visible. You can point at it, explain it, and perhaps take a nice screenshot.

An afternoon spent understanding a vague bug report is harder to celebrate. So is updating a dependency, clarifying an issue, checking a translation, or finding out why something only breaks in a particular environment.

Yet without that work, the impressive features gradually become less impressive.

### Keeping things usable counts

Monica isn't only the code we add. It's also the ability to install it, understand it, report problems, and keep using it after the surrounding ecosystem changes.

For an open source application, the range of environments makes that work particularly visible to maintainers and particularly invisible to almost everyone else.

Some tasks involve people rather than software. Explaining why a feature doesn't fit takes time. So does reviewing a contribution carefully enough to avoid accepting a long-term problem. Even saying no well is work.

This isn't a complaint about users asking questions. It's an explanation of where the available evenings go. A quiet release period doesn't necessarily mean that nobody touched the project.

It also helps explain why [GitHub activity](/en/handbook/github-stars/) is an incomplete picture. A thoughtful answer or a discarded approach can be valuable without producing a commit.

I enjoy releasing new things. I also want the things already released to keep working. Unfortunately, the second ambition has terrible screenshot potential.
