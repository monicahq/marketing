“Trust us” is an easy sentence to put on a website. It requires very little engineering.

For software like Monica, we'd rather give people ways to ask more specific questions. What does the code do? What information does a feature need? Can I run the application myself? What changes between versions?

Open source helps make those questions answerable.

### Inspection is a possibility, not a requirement

Most people using Monica won't read the code. That's fine. Choosing a personal CRM shouldn't require becoming a PHP developer.

What matters is that technically knowledgeable people can examine it, explain it, and challenge what we say. They don't need our permission to point out a mistake.

There are limits. Public source code alone doesn't prove how a particular server is configured or operated. It doesn't demonstrate that every vulnerability has been found. A self-hosted installation can also be misconfigured.

Those distinctions matter more than an attractive “open source = secure” badge.

[Why open source](/en/handbook/why-open-source/) explains the wider decision. Here, the point is accountability: questions about personal information deserve specific explanations, including where we don't know enough to make a claim.

We should be comfortable with verification that finds problems. That's part of its purpose.

I want people to trust Monica for reasons they can understand. Our panda looks honest, but I wouldn't accept it as a security audit.
