AI is interesting. It's also surrounded by an extraordinary amount of nonsense. Both things can be true at the same time.

For Monica, there are two separate questions. Can these tools help us build software? And should they do anything with the personal information inside the product?

Those questions deserve separate answers. A tool helping with a function doesn't automatically justify sending someone's family history to a model.

### Usefulness needs a specific meaning

I can imagine useful ways to make information easier to work with. But “we should add AI” isn't a problem statement. What is the person trying to do? What information would leave Monica? What could go wrong? Could a simpler feature solve the same problem?

A confidently invented detail about a friend isn't a charming creative flourish. It's incorrect personal information. Monica should help you preserve what you know, not make the gaps sound plausible.

And a suggestion about contacting someone is different from deciding how valuable that relationship is. We already have strong feelings about [automating friendships](/en/handbook/automating-friendships/).

This is a way of judging ideas, not an announcement of an AI feature or a description of where data is processed. Those details need to be explained for each actual feature.

I'm curious about the tools. I don't think curiosity requires handing them the keys to everybody's diary. Our [engineering article](/en/handbook/ai-development/) discusses the development side.
