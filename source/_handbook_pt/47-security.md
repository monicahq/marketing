Eu adoraria dizer que a Monica é completamente segura. Seria uma excelente frase para uma página de apresentação.

Seria também uma afirmação que não podemos fazer com honestidade.

A segurança depende de software, dependências, infraestrutura, configuração e pessoas. Tudo isso muda. Não encontrar nenhum problema conhecido hoje não significa que não haverá nada a encontrar amanhã.

### As consequências devem guiar o trabalho

A Monica guarda informações cuja sensibilidade nem sempre é óbvia pelo nome do campo. Uma nota simples pode conter algo intensamente pessoal. Isso deve moldar como pensamos sobre acesso, exposição acidental e as consequências dos erros.

As perguntas úteis são específicas. Quem deveria poder ler este registro? A mesma regra vale por outras interfaces? O que acontece quando o acesso muda? Uma mensagem de erro poderia revelar algo que não deveria?

Essas são perguntas que a engenharia deve responder, não uma afirmação de que este artigo certifica uma implementação ou um programa de auditoria específico.

[Testes](/pt/manual/testing/) e [código público](/pt/manual/verify-trust/) ajudam. Nenhum dos dois elimina a necessidade de investigar relatos e manter os sistemas envolvidos.

Se você descobrir uma possível vulnerabilidade, siga as instruções de relato de segurança do repositório atual. Por favor, evite publicar dados privados reais ou um guia de exploração funcional numa issue comum enquanto o problema está sendo avaliado.

Nas instalações hospedadas por conta própria, a sua configuração e a sua manutenção também contam. A segurança não é uma característica que possamos anexar a uma versão para depois parar de pensar nela. Irritantemente, ela continua dando trabalho.
