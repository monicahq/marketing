Uma funcionalidade nova é visível. Dá para apontar para ela, explicá-la e talvez tirar uma bela captura de tela.

Uma tarde gasta entendendo um relato de bug vago é mais difícil de celebrar. Assim como atualizar uma dependência, esclarecer uma issue, conferir uma tradução ou descobrir por que algo só quebra num ambiente específico.

Mesmo assim, sem esse trabalho, as funcionalidades impressionantes vão ficando, aos poucos, menos impressionantes.

### Manter as coisas utilizáveis conta

A Monica não é só o código que adicionamos. É também a capacidade de instalá-la, entendê-la, relatar problemas e continuar a usá-la depois que o ecossistema ao redor muda.

Para uma aplicação de código aberto, a variedade de ambientes torna esse trabalho particularmente visível para os mantenedores e particularmente invisível para quase todo mundo.

Algumas tarefas envolvem pessoas em vez de software. Explicar por que uma funcionalidade não se encaixa leva tempo. Revisar uma contribuição com cuidado suficiente para não aceitar um problema de longo prazo também. Até dizer não direito dá trabalho.

Isto não é uma reclamação sobre usuários que fazem perguntas. É uma explicação de para onde vão as noites disponíveis. Um período tranquilo sem lançamentos não significa necessariamente que ninguém mexeu no projeto.

Também ajuda a explicar por que a [atividade no GitHub](/pt/manual/github-stars/) é um retrato incompleto. Uma resposta cuidadosa ou uma abordagem descartada podem ser valiosas sem produzir um commit.

Gosto de lançar coisas novas. Também quero que as coisas já lançadas continuem funcionando. Infelizmente, a segunda ambição tem um péssimo potencial de captura de tela.
