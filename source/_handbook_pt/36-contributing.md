Você não precisa escrever PHP para tornar a Monica melhor.

Um relato de bug claro pode poupar horas. Uma tradução pode tornar o produto utilizável por alguém que, de outra forma, teria dificuldade. Uma explicação de um fluxo confuso pode revelar um problema que deixamos de notar meses atrás.

Essas são contribuições, mesmo que o GitHub não dê a todas elas um quadradinho verde.

### Comece onde o projeto está

Para código, leia as instruções de contribuição do repositório atual antes de começar. Elas são uma fonte melhor para os detalhes de configuração do que um artigo que pode sobreviver a três ambientes de desenvolvimento.

Para uma funcionalidade grande, converse primeiro sobre o problema. [Nosso artigo sobre priorização](/pt/manual/prioritize/) explica por que uma implementação funcionando não é automaticamente algo que conseguimos manter. Descobrir isso antes de gastar dois fins de semana é melhor para todo mundo.

Documentação e traduções merecem o mesmo cuidado que o código. Confira o que a interface realmente faz. Preserve o sentido. Se uma frase soar errada, explique por quê, em vez de transformá-la em silêncio numa promessa que não podemos cumprir.

Você também pode ajudar mostrando a alguém como a Monica funciona, compartilhando um retorno ponderado ou pagando pelo serviço hospedado, se ele for útil para você. O apoio financeiro importa, mas não compra controle sobre a direção do produto.

E, por favor, retire informações pessoais dos exemplos. Uma reprodução útil precisa do formato do problema, não do histórico médico do seu primo.

Contribua com algo administrável, explique com clareza e dê tempo para as pessoas responderem. Já é um ótimo começo.
