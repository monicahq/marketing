在 Hacker News 上发布 Monica 之后，我收到了很多问题，问我为什么选择用 PHP，尤其是 Laravel 来写这个工具。我其实很惊讶会有这么多人问这个话题，因为我认为语言本身并不重要，重要的是你用它做了什么。

这篇文章里，我会分享我为什么选择 PHP 和 Laravel，以及构建产品第一个版本时我需要克服的困难。这篇文章并不是要挑起语言之争。

PHP 有一段有趣的历史。很多优秀的 Web 开发者，现在或许已经不再使用 PHP，但他们正是从它开始学会编程基础的。它非常容易上手，用起来也简单，虽然算不上优雅的语言，却为人们在 Web 开发领域发展职业生涯铺平了道路。后来，PHP 渐渐不再受人喜爱，到了在聚会上提起自己公司用 PHP 都有点难为情的地步。其他语言，可以说更优雅的那些（Python、Ruby），借助构建在其上的出色框架大受欢迎。与此同时，新的 PHP 框架也出现了，比如 Symfony。但 Symfony 依然难学难用。然后，PHP 就“死”了。至少人们是这么说的，显然忽略了一个事实：**很多**企业仍然在使用它，而且用得很满意。再后来，PHP 5.5 发布了，接着是 PHP 7，还出现了一个名字古怪的新框架，Laravel。人们的观念彻底改变了。PHP 依然不如其他流行语言优雅，但情况已经好了很多。它也变快了。

尽管如此，PHP 仍然是人们喜欢吐槽的语言，尤其是在 Hacker News 上。他们说 PHP 无法扩展。这大概也是为什么 Facebook 和 Mailchimp 等大公司今天仍在以很大的规模使用 PHP。

### 基于这样的背景，我为什么选择 PHP 和 Laravel？

- PHP 容易学，也容易用。
- 会 PHP 的开发者很多。如果有人想一起做这个项目，至少在我所在的地方，PHP 开发者的潜在人数比 Ruby 或 Python 开发者更多。另外，GitHub 上也有很多人在用 PHP。如果我想让这个开源项目获得一些关注，就得用一种让不同编程水平的人都能轻松参与贡献的语言来写。
- 为新项目选择技术栈时，最重要的是长期维护起来有多容易。PHP 很简单。它容易调试（虽然还可以更好），也容易扩展（虽然我现在完全不用操心这一点）。
- Laravel 是我用过的最好的 PHP 框架，没有之一。它让复杂的事情变得很简单。这个框架显然是为了快速启动新的 Web 应用而创建的，用起来真是一种享受。但 Laravel 的杀手锏是文档的质量，无论与其他 PHP 框架相比，还是与许多其他语言的框架相比，都是如此。所有内容都有非常详尽的文档。好文档有多重要，我怎么强调都不为过（这也提醒我，应该把 Monica 的文档写得更完善）。
- PHP，尤其是 Laravel，周围有一个庞大的社区：Laracasts、Forge、Envoyer，还有活跃的 Slack 社区，这只是其中几个。如果你需要帮助，有很多人愿意伸出援手。

### 开发这个项目时，我遇到了哪些挑战？

总体来说，开发当前版本的 Monica 时，我没有遇到太多挑战。它不是一个复杂的应用，而且用户群还很小（总共约 7800 名用户，其中 4300 名活跃），所以也没有扩展方面的难题。但有一些实现细节我做得不对，并不是因为编码习惯不好，而是因为我当时的技术水平不足以在短期内解决那些问题。希望把这些错误列出来，能帮助其他人避免重蹈覆辙，或者让热心的朋友给我发邮件，告诉我本该怎么解决。

- 在早期版本中，我用了很多事件和监听器。这个概念很棒，但我在对基类做单元测试时遇到了很多问题。而且我用得越多，幕后发生的“魔法”就越多。我觉得，新加入代码库的人很难理解，比如创建一个对象时，为什么会发生某些事情。在我看来，事件和监听器会让应用更难理解，所以我决定把它们全部移除（准确说是 99%，还有两个监听器需要我去掉）。
- 一开始，数据库是完全加密的。出于我至今没搞明白的原因，解密过程时不时会出错，导致数据无法恢复。因为我当时不想处理这个问题，就决定去掉加密。而且，数据被加密后，查询中就无法进行任何排序或搜索，长远来看可能会出问题。我相信这两个问题都有解决办法，但我想把精力放在开发新功能上，而不是只修这一个问题。
- 在发布应用之前，我没有写单元测试。这让我吃了大亏。我不认为应该追求 100% 的测试覆盖率，但至少，要为网站的主要功能写一些测试。否则，你会遇到一大堆你没想到的 bug，而你在修复它们时，应用的其他部分又会被你的修复影响。这很快就会变成一场噩梦。Laravel 让单元测试变得非常简单，我本该更认真地对待。从 Laravel 的下一个版本开始，除非有单元测试，或许还要有功能测试，否则不会合并任何 pull request。

### 结论

以上就是我选择 Laravel 的一些原因。正如我在这篇文章开头所说，你的项目并不在于语言。除非你的项目本身就是为了学习一门新语言，否则不应该花上几周时间来选择语言或框架。用你熟悉的，直接动手做出点东西。你的用户不会在意你的代码是否丑陋，也不会在意你选了 Python 而不是 Ruby。
