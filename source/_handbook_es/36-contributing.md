No necesitas escribir PHP para mejorar Monica.

Un informe de error claro puede ahorrar horas. Una traducción puede hacer utilizable el producto para alguien a quien de otro modo le costaría. La explicación de un flujo confuso puede revelar un problema que dejamos de notar hace meses.

Todo eso son contribuciones, aunque GitHub no les dé a todas un bonito cuadradito verde.

### Empieza donde está el proyecto

Para el código, mira las instrucciones de contribución del repositorio actual antes de empezar. Son una fuente mejor para los detalles de instalación que un artículo que puede sobrevivir a tres entornos de desarrollo.

Para una función grande, discute primero el problema. [Nuestro artículo sobre priorización](/es/manual/prioritize/) explica por qué una implementación que funciona no es automáticamente algo que podamos mantener. Descubrirlo antes de dedicarle dos fines de semana es preferible para todos.

La documentación y las traducciones merecen el mismo cuidado que el código. Comprueba lo que la interfaz hace de verdad. Conserva el significado. Si una frase te suena mal, explica por qué en lugar de convertirla en silencio en una promesa que no podemos cumplir.

También puedes ayudar enseñando a alguien cómo funciona Monica, compartiendo comentarios meditados o pagando el servicio alojado si te resulta útil. El apoyo económico importa, pero no compra control sobre la dirección del producto.

Y, por favor, quita la información personal de los ejemplos. Una reproducción útil necesita la forma del problema, no el historial médico de tu primo.

Contribuye con algo abarcable, explícalo con claridad y da tiempo a que te respondan. Es un muy buen comienzo.
