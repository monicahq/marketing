你不需要会写 PHP，也能让 Monica 变得更好。

一份清楚的 bug 报告可以省下几个小时。一次翻译，可以让一个原本会用得很吃力的人用上这个产品。对一个让人困惑的流程所做的说明，可能揭示出一个我们几个月前就不再留意的问题。

这些都是贡献，即使 GitHub 不会给它们每一个都配上一个漂亮的绿色方块。

### 从项目现在的样子开始

如果是代码，动手之前先看当前代码仓库里的贡献说明。就搭建细节而言，它们比一篇可能比三个开发环境都活得久的文章更可靠。

如果是一个大功能，先讨论问题。[我们关于优先级的文章](/zh/handbook/prioritize/)解释了为什么一个能跑的实现并不自动就是我们能维护的东西。在你花掉两个周末之前就弄清楚这一点，对大家都更好。

文档和翻译值得与代码同样的认真对待。核对界面实际做了什么。保留原意。如果一个句子读着不对，请解释原因，而不是悄悄把它改成一个我们兑现不了的承诺。

你也可以通过给别人演示 Monica 怎么用，分享深思熟虑的反馈，或者在托管服务对你有用时付费来帮忙。资金支持很重要，但它买不到对产品方向的控制权。

另外，请把示例中的个人信息去掉。一个有用的复现需要的是问题的轮廓，而不是你表兄的病史。

贡献一点能处理的东西，说清楚，并给人们留出回应的时间。这就是很好的开始。
