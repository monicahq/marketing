有人在 GitHub 上给 Monica 点 star，我很高兴。这意味着他们注意到了这个项目，想关注它或表达欣赏。这很好。

但它不能告诉我们，他们有没有安装、有没有在用、有没有看懂，或者是否打算贡献。它当然也不能让托管服务商免掉账单。

star 是一个表示兴趣的信号。我们不该要求它去干别的活。

### 可见度会改变工作量

一个受欢迎的仓库，可以带来贡献者、有用的反馈，以及成为长期用户的人。它也可以带来超出一个小团队能应付的请求。

这些结果不会按便利的比例到来。十倍的关注，并不会带来十倍的维护能力。

按 star 数来比较项目，也忽略了它们各自想做什么。一个开发者工具，和一个存放私人家庭信息的应用，受众不同，安静使用的理由也不同。

对 Monica 来说，我更想知道的是：有人能不能找到多年前记下的一段记忆，贡献者能不能看懂代码，维护这个项目是否依然可持续。

其中有些问题，要浓缩成一枚徽章，难得多。

我们可以为关注而高兴，而不把它与[成功](/zh/handbook/success/)混为一谈。star 让更多人更容易发现 Monica。发现之后发生的事，才是更苛刻的部分。

不过，如果你点了 star：谢谢你。我也不是不会享受一个漂亮的数字。我只是不想让它当家作主。
